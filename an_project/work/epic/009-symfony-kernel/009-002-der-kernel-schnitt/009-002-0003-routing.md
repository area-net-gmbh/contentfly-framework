# Routing auf Symfony Routing

## Context
Die Routen entstehen heute über `$app['controllers_factory']` — eine `ControllerCollection` von
Silex, die beim Mounten in eine `RouteCollection` übersetzt wird. Die Sammlung ist der eine
Punkt, an dem die Provider den Kernel wirklich brauchen (siehe `Kernel\ControllerProviderInterface`
aus `009-001-0003`).

**`Route::$isSecure` ist das Empfindliche.** Es ist die Authentifizierungsentscheidung pro
Route und das, was beim Umschreiben von Routen als Erstes verloren geht — `012-006-0003` hat
das ausdrücklich festgehalten, und `RouteSecurityApiTest` prüft beide Richtungen. Die Routen der
Vorlage werden **als Daten eingelesen**, nicht einzeln übersetzt: `RouteManager::mount()` sammelt,
`bindRoutes()` bindet.

Dazu gehört, was `ServiceControllerServiceProvider` leistete: Ein Controller wird als
`"api.controller:listAction"` benannt — Dienst-Schlüssel und Methode. Diese Auflösung muss der
neue Kernel selbst mitbringen.

## Acceptance criteria
- [x] `RouteManager::mount()` und `bindRoutes()` behalten Signatur und Reihenfolge; ein Projekt
      merkt am Aufruf keinen Unterschied.
- [x] `Kernel\ControllerProviderInterface::connect()` bekommt einen echten Rückgabetyp — die
      Stelle, an der `009-001-0003` ihn bewusst offengelassen hat.
- [x] `"dienst:methode"` als Controller wird aufgelöst, ohne dass ein Provider dafür nötig ist.
- [x] Die Argumente einer Action werden weiterhin aufgelöst: `Request` und die Platzhalter aus
      dem Pfad (`/file/get/{id}/{size}/{alias}` und seine sechs Varianten).
- [x] `isSecure` wirkt unverändert: gesicherte Route ohne Token abgewiesen, ungesicherte
      erreichbar.
- [x] `bootstrap-web.php` mountet die vier Framework-Provider wie bisher.

## Verification
`RouteSecurityApiTest` und `FileApiTest` grün — der zweite deckt die sechs Pfadvarianten ab.
Dazu je ein HTTP-Aufruf auf eine gesicherte und eine ungesicherte Route der Vorlage.

## Ergebnis

**27 Routen, davon 18 abgesichert — dieselbe Zahl wie vorher, und dieselben.** Der
`RouteManager` behält Signatur und Reihenfolge; ein Projekt merkt am Aufruf keinen Unterschied.

### Vier Teile

`Routing\Routensammlung` ersetzt `$app['controllers_factory']` und bringt genau die drei
Methoden mit, die die Provider benutzen: `get()`, `post()`, `match()`. `Routing\Routeneintrag`
existiert für einen einzigen Zweck — `->before($checkAuth)` an eine Route zu hängen, was
Symfonys `RouteCollection::add()` nicht erlaubt, weil es nichts zurückgibt.

`Routing\ControllerResolver` löst `"dienst:methode"` gegen den Container auf. **Das ist, was
der `ServiceControllerServiceProvider` von Silex geliefert hat**, und es zählt, dass der
Container-Schlüssel eine faule Factory ist: Der Controller entsteht, wenn eine Route ihn trifft,
nicht beim Registrieren der Routen.

`Routing\AbsicherungListener` führt die `_before`-Rückrufe aus, auf `kernel.controller` — da hat
der Router die Route zugeordnet und der Controller ist aufgelöst, aber noch nicht gelaufen.
**Nur im Hauptrequest:** `ApiController::replaceAction()` schickt zwei interne Sub-Requests
(`009-001-0004`), und liefe die Prüfung dort erneut, müsste der Sub-Request den Token noch
einmal mitbringen — er trägt aber nur, was `Request::create()` ihm gegeben hat. In Silex lief
der `before()`-Filter am Controller ebenfalls nur für den Request, der die Route traf.

### Zwei Dinge, die beim Bauen anders kamen

**Die Sammlung kann nicht von `RouteCollection` erben.** Der erste Entwurf tat es — dann liegt
`mount()` eine fertige Sammlung vor, ohne dass jemand sie auspacken muss. PHP hat sofort
abgelehnt:

```
Declaration of Routensammlung::get(string $pfad, string $controller): Routeneintrag
must be compatible with RouteCollection::get(string $name): ?Route
```

`RouteCollection::get()` holt eine Route **beim Namen**, die Provider meinen mit `get()` das
HTTP-Verb. Zwei Bedeutungen für denselben Namen, und der geerbte gewinnt. Die Sammlung enthält
jetzt eine `RouteCollection` und gibt sie über `sammlung()` heraus; die fünf Provider schliessen
mit `return $controllers->sammlung();`.

**Pfade und Präfixe mussten normalisiert werden.** Silex hat das stillschweigend getan, und die
Aufrufer verlassen sich darauf: `CustomControllerProvider` baut `'/'.$route->route` zusammen,
und `custom/app.php` schreibt seine Route bereits mit führendem Schrägstrich — daraus wird
`'//bootstrap'`, was keine Anfrage je trifft. Ebenso beim Mounten: `bootstrap-web.php` übergibt
`'/api'`, `custom/app.php` `'api/v1/example/'`.

### Der Rückgabetyp, den `009-001-0003` offengelassen hat

`connect()` liefert jetzt `RouteCollection`. Damals war es bewusst offen: Der Rückgabewert war
eine `Silex\ControllerCollection`, und einen Typ zu setzen hätte Silex an genau der Stelle
festgeschrieben, an der er als Nächstes verschwand. Der Typ ist die allgemeinere
`RouteCollection`, nicht `Routensammlung` — damit ein Projekt seine Routen auch anders bauen
kann.
