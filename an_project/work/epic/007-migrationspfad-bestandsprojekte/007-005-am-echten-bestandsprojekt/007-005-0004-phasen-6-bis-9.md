# Phasen 6 bis 9 am Projekt durchspielen

## Context
Die zweite Hälfte: eigener Code, Authentifizierung, API-Vertrag, Daten. **Der Kern ist Phase 7**:
Sechs LoginManager, darunter OAuth 2.0 mit Profilabfrage, müssen auf `LoginProvider` aus
`013-004` umziehen. Genau dafür wurde dieses Projekt ausgewählt.

## Acceptance criteria
- [ ] Phase 6: Eigene Controller, Provider und Commands laufen auf dem neuen Kernel.
- [ ] Phase 7: Jeder der sechs LoginManager ist auf `LoginProvider` umgestellt oder begründet entfallen; der OAuth-2.0-Fluss inklusive Profilabfrage läuft so weit, wie `0002` ihn lokal durchspielbar festgestellt hat.
- [ ] Phase 8: Das Aufzeichnungsskript aus `0002` läuft gegen das migrierte Backend; **jede Abweichung ist erklärt** — beabsichtigt (mit Verweis in `breaking-changes.md`) oder Befund.
- [ ] Phase 9: Die Datenmigration (u. a. `appcms:security:reencrypt`, soweit das Projekt verschlüsselte Felder hat) ist auf der Kopie gelaufen.
- [ ] Die App (Ionic/Angular) ist gegen das migrierte Backend mindestens für Anmeldung und einen Kernablauf von Hand durchgespielt.
- [ ] Jede Hürde einsortiert wie in `0003`.
