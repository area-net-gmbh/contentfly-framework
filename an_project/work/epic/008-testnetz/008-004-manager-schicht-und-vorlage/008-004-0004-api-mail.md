# /api/mail festhalten

## Context
Der einzige Endpunkt der API mit **Aussenwirkung**: Er verschickt eine Mail. Alles andere
schreibt höchstens in die Datenbank.

```php
$mailto = $request->get("mailto");
if(!$mailto){
    return new JsonResponse(array('message' => "No mailto address"), 500);
}
$data    = $request->get("data", array());
$subject = $request->get("subject", "Anfrage über PIM-API");

$body = "";
foreach($data as $name=>$value){
    $body .= $name.":\t\t\t".$value."\n";
}

mail($mailto, $subject, $body, 'From: '.APP_MAILFROM);
```

## Umfang

### Was festzuhalten ist
- **Der fehlende `mailto`** liefert HTTP 500 mit `{"message": "No mailto address"}` — einer
  der wenigen Fälle, in denen das Framework eine eigene Fehlermeldung formuliert statt eine
  Ausnahme durchzureichen. Festhalten.
- Die Form der Erfolgsantwort.
- Der Aufbau des Rumpfs aus `data`: `name` + Tabulatoren + `value`, je Zeile.
- Die Absicherung: ohne Token abgewiesen.

### Der springende Punkt: kein echter Versand
`mail()` ist eine PHP-Funktion, kein Dienst im Container — es gibt keinen Punkt, an dem sich
eine Attrappe einhängen ließe, ohne den Code zu ändern.

Mögliche Wege, beim Umsetzen zu entscheiden und zu begründen:
1. **`sendmail_path` im Testserver** auf ein Skript oder `/bin/true` setzen, sodass nichts
   das System verlässt. Der Testserver wird ohnehin eigens gestartet.
2. **Nur die Fehlerfälle testen**, in denen `mail()` gar nicht erreicht wird (fehlender
   `mailto`, fehlender Token) — ehrlich, aber deckt den Erfolgsfall nicht ab.
3. `mail()` gibt bei fehlgeschlagener Zustellung `false` zurück; ohne konfigurierten MTA
   scheitert der Aufruf ohnehin. Ob der Endpunkt das an den Client meldet, ist selbst eine
   Zusicherung, die festgehalten gehört.

**Auf keinen Fall** darf ein Testlauf eine Mail an eine echte Adresse schicken. Wenn kein
sicherer Weg für den Erfolgsfall gefunden wird, bleibt es bei Variante 2 — mit Begründung im
Testkommentar.

## Acceptance criteria
- [ ] Der fehlende `mailto` ist mit Statuscode und Nutzlast festgehalten.
- [ ] Die Absicherung ohne Token ist festgehalten.
- [ ] Für den Erfolgsfall ist entweder ein sicherer Weg gefunden und dokumentiert, oder es ist
      begründet festgehalten, warum er nicht geprüft wird.
- [ ] **Kein Testlauf verschickt eine Mail nach draussen** — das ist nachweislich
      sichergestellt, nicht angenommen.

## Verification
Mehrere vollständige Läufe. Der Nachweis, dass nichts hinausgeht, gehört ausdrücklich in die
Verifikation — etwa über die Konfiguration des Testservers.
