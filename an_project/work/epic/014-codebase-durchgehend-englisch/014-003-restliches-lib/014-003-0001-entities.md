# Entities auf Englisch

## Context
Security, Controller und Commands rufen Entity-Methoden auf. Die Entities kommen deshalb zuerst.

Umfang: alle 22 Dateien unter `lib/contentfly/Entity/`. Bekannte deutsche Namen:
- `Token::hashen()` → `hash()`
- `Token::ZWECK_REFRESH` → `PURPOSE_REFRESH`; der gespeicherte Wert `refresh` bleibt
- `Token::istRefreshToken()` → `isRefreshToken()`
- `Token::getKlartext()` → `getPlaintext()`
- `User::brauchtNeuenHash()` → `needsRehash()`
- `User::passwortSperren()` → `lockPassword()`
- `User::verfahren()` → `algorithm()`

Dazu kommen alle Kommentare, Meldungen und privaten Namen der Entities. Tabellen- und
Spaltennamen sind englisch und bleiben.

## Acceptance criteria
- [x] Die Dateien des Tasks sind vollständig englisch: Namen, Methoden, Eigenschaften, Variablen, Konstanten, Meldungen und Kommentare.
- [x] Werte, die gespeichert oder über die API ausgeliefert werden (Tabellen- und Spaltennamen, Message-Keys, Token-`purpose`), bleiben unverändert, wenn sie schon englisch sind. Ein deutscher gespeicherter Wert wird nur nach Rückfrage geändert.
- [x] Alle Aufrufer im Baum sind mitgezogen (`lib`, `custom`, `bin`, `tests`, `tools`, `.gitlab-ci.yml`, `phpstan.neon.dist`, `rector.php`, `dev-guide.md`, soweit ein Test daran abgleicht). Testklassen, die nach einer umbenannten Klasse heissen, sind mit umbenannt.
- [x] Die Ausnahmen im Sprachwächter, die dieser Task auflöst, sind gestrichen.
- [x] Verhalten unverändert: volle Suite mit gleicher Testzahl, PHPStan `[OK]`, Deprecation-Gate grün, `console list` läuft, `custom/config.php` ohne Zugangsdaten.

## Verification
Volle Suite gegen `contentfly-db-0004` mit Vergleich der Zahlen, PHPStan (Result-Cache geleert),
`tools/ci/deprecations-pruefen.sh`, Nachsuche nach jedem alten Namen (auch in umgebrochenen Aufrufen),
Suche nach deutschen Wörtern in den Dateien des Tasks, `sh tools/check-template-config.sh`.

## Ergebnis

**Alle 22 Entities sind englisch.** Umbenannt sind:
- `Token::hashen()` → `hash()`
- `ZWECK_REFRESH` → `PURPOSE_REFRESH`
- `istRefreshToken()` → `isRefreshToken()`
- `getKlartext()` → `getPlaintext()`, samt Eigenschaft `$plaintext`
- `User::brauchtNeuenHash()` → `needsRehash()`
- `passwortSperren()` → `lockPassword()`
- `istPasswortGesperrt()` → `isPasswordLocked()`
- `istAltformat()` → `isLegacyFormat()`
- `verfahren()` → `algorithm()`
- `PASSWORT_GESPERRT` → `PASSWORD_LOCKED`
- `$rollen` → `$roles`

**Werte, die gespeichert werden, sind unverändert:**
- der Token-`purpose` `refresh`
- das Sperrzeichen `*` im Passwortfeld
- alle Tabellen- und Spaltennamen

**Zwei Werte, die über die API ausgeliefert werden, sind englisch geworden.** Es sind die
Beschriftungen der Auswahlfelder, nicht die gespeicherten Werte:
- `Group.apiQueryEnabled`: `disabled=not allowed, enabled=allowed`
- `Log.mode`: `UPT=Modified, DEL=Deleted, INS=Created, USERDEL=Deleted for`

Die Schlüssel (`disabled`, `UPT` …) bleiben. Das `/api/schema` liefert damit englische Labels,
und kein Test prüft die alten Texte.

**Arbeitsweise:** Die Kommentare haben zwei Agenten parallel übersetzt, mit der festen Regel
„nur Kommentare". Nachgeprüft ist das mechanisch: In allen 22 Dateien sind die PHP-Token ohne
Kommentare identisch mit dem Stand davor. Erst danach habe ich die Namen umbenannt und die
Aufrufer mitgezogen: `TokenHandler`, `UserProvisioning`, `AuthController`, `SystemController`,
`TokenHandlerTest` und `UserProvisioningTest`. Im Sprachwächter sind acht Ausnahmen gestrichen.

Geprüft: volle Suite `OK (528 tests, 1702 assertions)` wie vorher, PHPStan `[OK] No errors`,
Deprecation-Gate grün. Die Suche nach deutschen Wörtern in allen Entities findet nichts.
