# /commit — commit the current changes

**Args:** `$ARGUMENTS` — all optional, order-independent, split on whitespace:
- `--de` / `--en` — message language for this run only.
- a token starting with `http://` or `https://` — the ticket URL.
- at most one remaining token, matching `^#?\d{3}-\d{3}-\d{4}$` — the work-item id. Strip a leading `#` immediately, so from here on the id is bare `EEE-SSS-TTTT`.

Any other token — a stray flag, a free-form string — **stop and ask**. Never read a free-form string as an id.

## Steps
1. **Preflight** — run each probe. On any hit stop, report it and the way out; stage nothing, commit nothing.
   - `git symbolic-ref --short -q HEAD` exits non-zero → detached HEAD; the commit would be unreachable from every branch. (Never `git branch --show-current` — git ≥ 2.22 only.)
   - `git rev-parse -q --verify MERGE_HEAD` / `CHERRY_PICK_HEAD` / `REVERT_HEAD` exits 0 → finish or abort that operation first; `/commit` never rewrites its message.
   - `git rev-parse --git-path rebase-merge` prints a path; run `test -e <that literal path>` as a **separate** command, then the same for `rebase-apply`. Either exits 0 → rebase in progress. Keep the `git` call out of `$( … )`: a substituted argument cannot match a permission rule, so it prompts on every run. Never test `.git/…` directly; in a worktree `.git` is a file.
   - `git diff --cached --name-only -- ':(top).an_framework'` prints anything → framework files are **staged**. Since v2 the core `.an_framework/` is committed as ordinary files, so — unlike the old submodule — git no longer hides it and it *can* be staged; `/commit` still never records it as project work. `:(top)` is required — a bare pathspec is cwd-relative. Probe **staged**, not merely dirty: an in-progress framework install/update leaves `.an_framework` dirty, and blocking every routine commit on that would cry wolf. This staged change is not folded into project work — hand over the right commit instead, discriminating with `git rev-parse -q --verify HEAD:.an_framework`:
     - that **fails** → `.an_framework` is not in `HEAD` yet, so this is the **initial setup commit** that first introduces the whole core. The init script prepares it with named paths (never `git add -A`) — see `.an_framework/tutorial/quickstart.md`, setup step. (Do not test `git rev-parse -q --verify HEAD` instead: that only detects a repository with no commits at all, and would misdiagnose adding the framework to a project that already has history.)
     - that **succeeds** → the core is already committed, so this is a **framework update**. It belongs in its own `chore(framework): …` commit covering only the staged `.an_framework` paths, never mixed with project work.
     `/commit` makes neither. To continue with project-only work, unstage the core with `git reset -q -- ':(top).an_framework'`; to record the framework change, make the dedicated commit by hand. This is the only content `/commit` refuses to stage on purpose.
2. **Read the conventions** — `.an_framework/docs/git-conventions.md` for format, types, `Ref:` and language. The project narrows it in `an_project/docs/git.md` — read that too; **on conflict the project file wins**. A missing or empty overlay is valid: the baseline stands alone, don't stop.
3. **Check the branch** — if HEAD is the integration branch (named in `an_project/docs/git.md`, otherwise `master`, `main` or `develop`), quote the rule and offer `git checkout -b <type>/<EEE-SSS-TTTT>-<kurz-slug>` (never `git switch` — git ≥ 2.23 only). Continue only on an explicit go-ahead.
4. **Inspect** — `git status --porcelain=v1 -z -uall` for the state, `git diff --staged` for the content; the content is the only source of a WHY. The `-z` is not optional: without it a path with an umlaut, a space or a quote comes back C-quoted (`"\303\234bung datei.txt"`) and is useless as a pathspec. Records are NUL-terminated, and a rename or copy (`R`/`C`) is **two paths**, new then old. Never branch on git's human-readable output — it is localised. Nothing staged → list the candidates, ask which to stage, stage exactly those with `git add -- ':(top,literal)<path>' …`, then re-read the diff. Never `git add -A`, `git add .`, `git add -u` or `git commit -a`, and **never offer or stage anything under `.an_framework/`** — the core is read-only; git surfaces its files as ordinary candidates now, and a framework change is its own commit (step 1).
5. **Screen** — stop if a staged path looks like a credential: `.env`, `.env.*` (except `*.example` · `*.dist` · `*.sample`), `*.pem`, `*.key`, `*.p12`, `id_rsa*`, `id_ed25519*`, `*credentials*`. Name it, then split the two cases with `git cat-file -e HEAD:<path>`:
   - **not in HEAD** → `git reset -q -- ':(top,literal)<path>'` drops it back to untracked and a `.gitignore` line then bites. Offer both; that is the whole fix.
   - **in HEAD** → say plainly that the secret is already in history and in every clone. `git reset` only un-stages the new version, and `.gitignore` is never consulted for a tracked path. Offer `git rm --cached -- ':(top,literal)<path>'` plus the ignore line, note that this leaves a staged deletion and that the value must be treated as leaked and rotated. Purging history is out of scope.
6. **Group** — cluster the staged files by fachlicher Intention; one cluster = one commit. A file belongs to exactly one cluster — a pathspec commit cannot split one file's hunks, so if a file's staged changes span two intentions, say so and let the user re-stage. Both halves of a rename belong to the same cluster.
7. **Resolve the id** — first hit wins: the argument · the branch name `<type>/<EEE-SSS-TTTT>-<slug>` · the single item in `an_project/work/` whose frontmatter says `status: in-progress` at task level (`TTTT` ≠ `0000`; more than one hit → skip). Argument and branch disagreeing → stop and ask — **with one exception, the story branch**: since v2.2 `/implement <story-id>` puts a whole story on one branch and commits its tasks onto it one by one, so an argument that is a *child task of the branch's story* is not a disagreement. Accept it, and use the **argument** (the task id) — that is the commit's real subject. The exception is deliberately narrow, so a genuine mix-up still stops the run; it holds only when **all three** are true: the branch id ends in `0000` at task level, the argument does not, and their `EEE-SSS` are identical. Anything else — two different stories, a task id on a *task* branch, an epic id anywhere — disagrees as before. Then **verify it**: an id from the first two sources must match a work item's frontmatter `id:` (a mention in `depends_on` or a checklist doesn't count). No match → report where the id came from and ask, rather than writing a `Ref:` to nothing. Nothing resolves, or there is no `an_project/work/` at all → commit **without** a `Ref:` line, but only after the user confirms. Never invent an id, never `#000-000-0000`.
8. **Draft** — one message per cluster, in the resolved language, in the baseline format. Take `<scope>` from the Scopes section of `an_project/docs/git.md`; if that is still empty, propose one and mark it as unconfirmed. Add the `WHY` / `WHAT` / `AFFECTS` body only where the change needs explaining. With a ticket URL, put `Ticket: <url>` on its own line under `Ref:` — never inside it.
9. **Confirm once** — print every message in full under a `Commit n/N` heading, with the files it covers and, where there is one, the id's source and the title of the work item it resolved to. State that confirming creates N commits in that order. Then wait: the user may confirm, reword, regroup, or stop.
10. **Commit** — pipe the message in. Never `-m`: double quotes execute backticks and expand `$`, single quotes break on an apostrophe — the shell, not the draft, would decide what the message says.

    ```sh
    git commit -F - <<'KI_COMMIT_MSG_EOF'
    <the full message>
    KI_COMMIT_MSG_EOF
    ```

    The delimiter is quoted and sits at column 0. One cluster → no pathspec, and the commit is the index exactly as reviewed. For **several** clusters, `git commit -F - -- ':(top,literal)<path>' …` records the **worktree** content of those paths, not the index — so re-run `git diff -- <that cluster's paths>` immediately before *each* commit, not once up front. Non-empty → stop before that commit and ask; something dirtied the worktree mid-run, most likely a `pre-commit` hook that reformatted a file. List every path of the cluster, both halves of a rename included — committing only the new path leaves the old one in the tree and strands its deletion in the index. `:(top,literal)` is load-bearing: `literal` stops a path containing `[`, `*` or `?` from acting as a glob, `top` keeps it root-relative.
11. **Verify** — a non-zero exit stops the whole run: print git's stderr verbatim and unparsed, leave the index untouched, and never retry with `--no-verify` or `--no-gpg-sign`. If commit *k* of *N* failed, lead with that: name what already landed (`git log --oneline`), state that the remaining clusters are still staged unchanged so a re-run resumes with exactly those, and undo nothing — that call is the user's. On success report `git log --oneline -<N>`; anything still staged afterwards means a pathspec was incomplete, typically the old half of a rename. Finally name any committed file that `git diff --name-only HEAD -- <those paths>` still lists: what landed is not what is on disk. That probe cannot say why — offer both readings, ordinary unstaged work in that file or a hook that edited it after staging, and say which this run makes likely.

Writes no file and no `an_project/CHANGELOG.md` entry — the command that produced the change already logged it. If `an_project/CHANGELOG.md` is already modified for the work being committed, stage it with the change it describes; across several commits attach it to the last one and say so. Never `git push`, never `git commit --amend`, and never stage or commit anything under `.an_framework/` as part of project work.
